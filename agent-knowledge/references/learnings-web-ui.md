# Web UI Learnings — Self-Contained HTML Pages, Theming, and Proving a Render

Portable patterns for no-build, single-file HTML pages: layout, persistent UI state, theming, and render verification.

See also: `learnings-validation-framework.md`, `learnings-agent-workflow.md`, `learnings-observability.md`, `learnings-code-review.md`.

## Layout that survives real content

1. **Cap a CSS multicol layout at 2 columns, and reach for CSS grid the moment a tile needs an addressable POSITION.** Chrome's multicol balancer is greedy, not optimal: with 4 unbreakable blocks in 3 columns it left column 3 entirely **empty** (measured). With n≥2 blocks, 2 columns provably always fill both. But multicol has no addressable slots, so a tile cannot be *dropped at an index* — the drag-arrangeable form is CSS grid with `1px` auto-rows, `grid-auto-flow: row dense`, `align-items: start`, and a JS-measured `grid-row-end: span <height+gutter>` per tile. Measured on a real 5-panel payload at 1400 px: grid 589 px tall / 57 px ragged vs multicol 608 px / 99 px — **neither dominates on compactness**, so choose on addressability, and `dense` is what keeps grid from leaving the mid-page hole that plain `align-items:start` grid does (230 px when a 2-row panel sits beside a 7-row one). Keep the rule structural and name-free: a `:has(.panel:nth-child(2))` guard leaves a single-panel page full width, and no panel name ever appears in the CSS.

2. **Resize a content-sized tile in whole column spans, never free pixels.** Panels are content-sized, so free resize only buys dead space under the last row. A 1-or-2 column span button is also keyboard-operable for free.

3. **Long-value overflow: shrink the GROWING side, cap the FIXED side — do not reach for proportional flex shrink.** A value clipped mid-glyph at the panel edge is `flex: 0 0 auto` with no cap; the obvious fix (let both sides shrink proportionally) ate a *short* label instead (`AWS` → `A…`). Correct pattern: the label shrinks freely with `min-width: 0`, the value stays `flex: 0 0 auto` but gets a `max-width` (~78 % of a row) plus ellipsis. ⚠️ A **chip reverses it** (`label: flex 0 1 auto`, value capped) because a chip reads as one sentence, not a table line.

4. **Never pick a display face for a surface that carries counts or timestamps without rendering the digits 0-9 and LOOKING at them.** Big Shoulders Display renders `1` as a bare vertical stroke with no flag: a headline `1 needs you` read as `I needs you`, and a toggle `DONE (10)` read as `(IO)`. Rejected for Oswald. Verify a webfont actually loaded with `document.fonts.check`, not by eye.

5. **A `::after` pseudo-element is the last child, so at equal `z-index` it paints OVER the content — ties break by tree order.** If that is the intended look, say so, and be careful "fixing" it: raising content to `z-index: 2` changed a real page at ≤520 px viewport width (3,462 differing pixels on a wide-content fixture) while looking like a no-op at desktop width. Also watch for a **duplicate rule of equal specificity earlier in the sheet** — it is dead code that reads as the live rule.

## State in a page that rebuilds itself

6. **If a poll rebuilds the DOM, UI state CANNOT live in the DOM.** Keep a module-level map keyed `<panel>/<groupKey>`, hydrate it once from `localStorage` in a `try`/`catch` IIFE, and re-read it on every render — storage is a **write-through cache only**, so blocked or throwing storage degrades to session-only memory instead of breaking the render.

7. **Never interpolate a plugin-supplied key into a CSS selector — iterate `list.children` and compare instead.** A collector/plugin that supplies group keys is supplying selector injection if you do `querySelectorAll` with the key interpolated. Keeping the key to `localStorage`, `node.dataset`, and a string compare makes any string safe, which in turn lets the keys be **data-derived** (e.g. one dropdown per parent item that currently has active children) rather than a fixed list.

8. **Skip the rebuild when nothing changed: key the render on a stable serialization of the payload.** A 5 s poll that rebuilds the whole grid every tick destroys focus, hover, selection and scroll. The fix is ~6 lines and name-free: `JSON.stringify(data, (k,v) => k === '<the per-poll timestamp field>' ? 0 : v)` and skip when the key is unchanged. ⚠️ **Update the freshness stamp BEFORE the skip check** so relative times keep aging.

9. **Because of #8, a flapping row ORDER rebuilds the page every tick — any collection built from a `set`/`dict` needs a total order.** Set iteration is hash-randomised per process, and `python3 -I` implies `-E`, so `PYTHONHASHSEED` cannot pin it: 6 runs of one real collector gave **2 distinct orders** for rows with equal sort keys. Fix: append a stable id as the final element of **every** sort key, including secondary sorts. The test is to **hash the row order over ≥6 consecutive runs**, not to eyeball one.

10. **Persisted layout should name only what the user moved.** `{order: [names], span: {name: n}}` keyed by panel name, loaded into a module-level object in `try`/`catch`. A stored arrangement reorders **only the panels it names**, so a brand-new panel lands after everything the viewer placed and disturbs nothing, and a panel the payload drops keeps its stored entry (ignored, never resurrected as an empty tile). ⚠️ Defer a rebuild while a pointer drag is live and flush it on `pointerup`, or a poll tears the tile out from under the pointer.

11. **Drag a tile with pointer events on `window`, not `setPointerCapture`.** `insertBefore` detaches the node and can release capture. Guard the handler with `ev.target.closest('button, a')` so toggles still click and links still follow their href, and keep the dragged tile **in flow** so the grid repacks under the pointer (the drag is then WYSIWYG). Keyboard path: a grip button toggles a pick-up mode (`aria-pressed`), arrows move ±1 with an `aria-live` position announcement, Enter/Escape drop.

## Theming: default, toggle, and the migration between them

12. **A dark-first default must live in CSS — bare `:root` is dark, `[data-theme="light"]` is the opt-out — never "JS stamps dark when storage is empty".** The JS shortcut falls back to `prefers-color-scheme` with JS disabled, so a system-light no-JS visitor gets light and the stated default silently does not hold. Flipping the default also makes any `matchMedia` change listener dead code (nothing follows the system any more) and requires the `color-scheme` property **and** the `<meta name="color-scheme">` order to flip, or the UA scrollbar stays light on first paint.

13. **A zero-JS toggle that honours the system preference AND an explicit stamp needs FOUR token blocks, not two.** Bare `:root` (light); `@media (prefers-color-scheme: dark)` + `:root:not([data-theme="light"])` — the plain required rule with **no `:has`**, so system dark still works in browsers without `:has()`; `@media dark` + `:root:not([data-theme]):has(#flip:checked)` (light reset); `@media light` + the same `:has` (dark). The checkbox means **INVERT the system preference**, not "dark on" — that is the only 2-state control that can honour a 3-state default. Guard the `:has` rules with `:not([data-theme])` so they are mutually exclusive with the explicit stamp; otherwise `:has()` specificity (1,2,0 via the id argument) beats `:root[data-theme="dark"]` (0,2,0) and the stamp **silently loses**. Set `color-scheme` in every block. Tradeoffs: no persistence across reload, and the box reads "unchecked" while a system-dark page is dark.

14. **Migrating that toggle from CSS-only to JS (`data-theme` + `localStorage`) is NOT additive — the `:has()` flip blocks must be DELETED.** The checkbox's meaning changes from "invert the system preference" to "the page is dark". Once JS syncs `checked` to the **resolved** theme on load (which is what fixes the screen-reader "unchecked while dark" defect), the old `:root:not([data-theme]):has(#flip:checked)` matches under system-dark-with-nothing-stored and inverts the page to light — and its (1,2,0) specificity beats the (0,2,0) `@media` rule. Measure it on the real file before removing. ⚠️ `localStorage` is **blocked on `file://` origins in Chromium**, so persistence must be tested over HTTP (a tiny static server) or a local pass proves nothing.

15. **Colour role discipline beats hue tuning: resolve a warn-vs-accent collision by ROLE plus hue distance, not hue alone.** The rule that held across three palette revisions of one page: **semantic colour appears ONLY as a row/chip left edge; the brand accent appears ONLY on chrome and interaction** (brand mark, top rule, link hover, focus ring, open-group toggle) and never as a status band; a third material, if any, is used by exactly one element and is cool enough that it cannot be read as the accent. With roles fixed, keep the semantic band a traffic-light ramp and buy separation with hue distance (a garnet crit at h≈351 is 39° off a sodium warn; a vermilion red would be only 21°). Supporting choices that carried the range without more hues: a blue-black ground rather than `#000`, cool surfaces against **warm** text (the temperature split is the range), and a dim `ok` because *ok is the absence of a problem*. **Zero hardcoded hex outside `:root`.**

16. **The unconfigured state must keep its OWN message, so a setup problem is never hidden behind a reassuring all-clear.** "Nothing to report" and "nothing is wired up" look identical to a page that only counts rows. Give the empty-because-healthy state copy that is the direct negative of the alarm state, and give the empty-because-unconfigured state its own headline plus a pointer to the contract/doc that adds a source.

## Proving it renders, with no test framework

17. **Run the page's own `<script>` headlessly under `node:vm` against a ~40-130 line DOM shim, and serialize the resulting tree as indented text.** Extract the script body with a regex, build `createElement` / a `textContent` setter that clears children / `appendChild` / `classList` / `dataset` / `getElementById` / `querySelectorAll`, run it with `vm.createContext` + `runInContext` and a `fetch` stub returning the real payload. That yields **genuine rendered output** — class names, hrefs, text — as evidence. To prove a change is a no-op, reconstruct the PRE-change template in a scratchpad and diff old-vs-new render output for an unchanged payload. ⚠️ **The negative control is a one-field mutation** that must flip the render (drop an `urgent: true` and the page must go from attention to all-clear); an unchanged-input comparison is not a control.

18. **The shim is useless for anything CSS-dependent — overflow, focus rings, computed fonts, `prefers-reduced-motion`, actual key handling — so drive real headless Chrome over CDP.** Node's global `WebSocket` plus `/json/list` is enough; no puppeteer, no npm. Four gotchas that each cost real time: **(a)** `Input.dispatchKeyEvent` needs `type: 'keyDown'` **with `text: '\r'`** for Enter to synthesize a click on a focused button — `rawKeyDown` + `keyUp` alone does nothing. **(b)** `getComputedStyle(el, ':focus-visible')` silently returns nothing (pseudo-**classes** are unsupported) — use `CSS.forcePseudoState` with `DOM.enable` + `CSS.enable`. **(c)** To test storage that throws, inject `Object.defineProperty(window, 'localStorage', {get(){throw}})` via `Page.addScriptToEvaluateOnNewDocument` so it lands before the page script. **(d)** Chrome's `--window-size` **clamps at 500 px on macOS**, so a narrow-viewport check must use `Emulation.setDeviceMetricsOverride`; `Emulation.setEmulatedMedia` is how you toggle `prefers-reduced-motion` / `prefers-color-scheme`.

19. **For behavioural probes, have the test server inject a driver `<script>` and a `<pre id=probe>` before `</body>`, click the real buttons, call the page's own global render, then scrape `--dump-dom` for the probe text.** Two traps: `document.body.textContent` **includes injected `<script>` source**, so assert on specific nodes rather than page text; and an absolutely-positioned or wide `<pre>` probe creates horizontal overflow that **poisons a `scrollWidth` check** — hide it first.

20. **Pixel-exact A/B with no build step: serve template + a FROZEN payload from a throwaway `http.server`, inject `Date.now = () => FIXED` at `<head>` identically on both sides (file untouched) so relative timestamps are deterministic, then `--screenshot` with `--virtual-time-budget` to wait out webfont load.** PNGs diff with a ~40-line stdlib `zlib` + `struct` decoder; no PIL needed. The frozen snapshot is the load-bearing part — live data moves, and before/after on moving data proves nothing.

21. **Report the BOUNDING BOX of differing pixels, not just a count.** That is what shows a change is confined to the element you touched (one real result: 95×14 CSS px in a nav rail, 0.0041 % of a 2880×17502 page). For a theme-following SVG the control is the opposite: light-vs-dark diffs ~99.9 % of its pixels, and a histogram of the UNCHANGED remainder proves it is anti-aliasing mid-tone rather than a hard-coded colour that failed to follow.

22. **Playwright `fullPage` screenshots are NOT a valid pixel-diff baseline when the page has `position: sticky`.** Chromium scroll-and-stitches the capture, so a sticky element whose **height** changed between builds is painted at slightly different offsets and fabricates a diff region that looks like a regression — observed as two hairlines "brightening" while `getComputedStyle` showed the elements byte-identical (same rect, same transparent border). **Fix: render the whole page in ONE tall viewport (`viewport.height = document.scrollHeight`)** — no scroll, no stitch seam, sticky never engages. ⚠️ **General rule: when a pixel diff disagrees with computed styles, suspect the CAPTURE before the page.**

23. **To prove a theme DEFAULT flip, prove the system preference is IRRELEVANT — render each storage state under BOTH `colorScheme` emulations and pixel-diff them, expecting 0 px.** Asserting computed styles alone does not rule out a surviving `@media` rule. Pair it with a negative control (the OLD file under light vs dark emulation, which must differ) so a 0 px result cannot be a broken capture. Playwright's `newContext({colorScheme})` emulates `prefers-color-scheme`, which Chrome's CLI flags cannot do; if Playwright is not installed, check `~/Library/Caches/ms-playwright` first — a cached chromium plus `npm i playwright-core` in a scratchpad is often enough.
